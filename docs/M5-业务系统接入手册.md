# M5 PPS 业务系统接入手册

> 版本：v1.0 · 日期：2026-08-02 · 读者：业务系统开发者（不要求隐私计算背景）

## 1. 你需要知道的最少概念

- **能力（Capability）**：你唯一要关心的调用单元（如 `credit-check` 信用核验）。
  ε、协议、输出粒度等隐私参数**由平台与合规方预置**，你不可见也不需要关心。
- **幂等键（reqId）**：你生成的全局唯一 id，**建议直接用业务单据号**。带同一 reqId 重试
  保证不重复执行、不重复扣费。
- **两种调用模式**（由能力决定，你只管按对应 API 调）：
  - **同步查询**（毫秒级，如匿踪查询）：一次 RPC 拿结果，可入交易主链路；
  - **异步作业**（秒级~小时级，如 PSI/联合统计）：提交拿 jobId，回调或轮询取结果。

## 2. 接入前准备

1. 向 PPS 管理员申请 **appId + appSecret**（密钥仅你保管，PPS 侧只存信封加密副本）；
2. 申请所需**能力授权**（哪个 app 能调哪个能力、日配额多少）；
3. 拿到 PPS 节点地址（如 `https://pps-node-a.internal:8443`）。

## 3. 同步查询（模式 A）

```java
PpsClient pps = new PpsClient("https://pps-node-a.internal:8443", "risk-system", secret);

// 幂等键 = 业务单据号；协议/ε 对你不可见
PpsClient.QueryResult r = pps.query("credit-check", customerId, loanOrderId);
if (r.hit()) {
    useScore(r.value());
}
// r.appQuotaRemaining() 可用于业务侧限流预警
```

错误处理：`PpsCallException` 的 `retryable()` 为 `true`（5xx/网络）才重试，
且**必须带同一 reqId**（幂等保证不重复执行）；4xx（认证/授权/配额/参数）不要重试。

## 4. 异步作业（模式 B）

**回调方式（推荐，业务系统有公网/内网可达回调地址时）**：

```java
PpsClient.JobHandle job = pps.submit("joint-consumption-stats", params, batchId,
        "https://risk.internal/pps-callback");   // 立即返回，不阻塞
// job.jobId() == batchId
```

回调到达时（你的 `/pps-callback` 端点收到 POST），**务必验签**确认来自 PPS：

```java
boolean genuine = pps.verifyCallback(jobId, state, summary, timestamp, nonce, signature);
if (genuine && "SUCCEEDED".equals(state)) {
    var result = pps.getResult(jobId, 0, 1000);   // 分页拉取大结果
}
```

**轮询方式（回调不可达时的兜底，始终可用）**：

```java
while (true) {
    var s = pps.getJob(batchId);
    if (s.state().equals("SUCCEEDED")) { var r = pps.getResult(batchId, 0, 1000); break; }
    if (s.state().equals("FAILED")) { handleFailure(); break; }
    Thread.sleep(3000);
}
```

**脚本/批处理便捷**：`pps.awaitResult(capability, params, reqId, timeoutMillis)` 一步到位
（阻塞至终态返回结果，仅用于无法接收回调的批处理，不要用于在线主链路）。

## 5. 结果拉取三档（对你透明）

- 小结果：一次返回；
- 大结果：`getResult(jobId, cursor, limit)` 分页，用返回的 `nextCursor` 续拉直到 `hasMore=false`。

## 6. 必须遵守的三条

1. **reqId 全局唯一且可复现**——用业务单据号，重试用同一个；
2. **同步能力入主链路必须有降级预案**——PPS 不可用时的业务兜底规则由你实现；
   SDK 默认超时，不会无限等待；
3. **回调一定验签**——防伪造终态。

## 7. 可观测

PPS 节点暴露 `GET /pps/v1/metrics`（Prometheus 文本）：
`pps_requests_total`（按能力/状态）、`pps_latency_millis_*`（按能力）。接入你的监控体系。

## 8. 你不需要做的事（PPS 已保证）

- 不需要理解 PSI/PIR/差分隐私/联邦学习；
- 不需要设置 ε、选协议、定输出粒度——这些由能力目录预置，且其变更需双方审批；
- 不需要管跨方通信加密（mTLS/TLS 隧道由 PPS 负责）。
