## 3. 未达成项与遗留（诚实声明）

**B1｜`flow model load` 下发失败 —— 已解决（2026-08-01）**

根因是**三层叠加**，逐层定位（修复已固化进 `deploy/fate/publish-model.sh` 与 `start-standalone.sh`）：

| # | 根因 | 症状 | 修复 |
|---|---|---|---|
| 1 | 模型未 `deploy` | `retcode 100: Only deployed models could be used to execute process of loading` —— 该行此前被 `tail` 截断而漏读 | 先 `flow model deploy` 生成可部署版本，再对**新版本号** load |
| 2 | `servings` 指向错误端点 | 指 proxy:8059(HTTP) → gRPC `UNAVAILABLE`；指 proxy:8879(gRPC) → `Method not found: ModelService/publishLoad` | 必须指 **serving-server:8000**（`ModelService` 的宿主；proxy 只管推理路由，不管模型下发） |
| 3 | `fateflow.host=0.0.0.0` | Serving 侧 `model initialization error`——该值被写进下发的 transfer URL `http://0.0.0.0:9380/...`，在 Serving 容器内不可路由 | 改为**容器真实 IP**（配置文件原注释即警告 "127.0.0.1 and 0.0.0.0 is not supported"） |

**验证**：`publish-model.sh <jobId>` 对两个不同训练任务各跑一次，deploy/load/bind/推理全部 retcode 0。

**B1b｜分值恒 0（新发现，业务接入项而非缺陷）**：`feature.single.adaptor=MockAdapter`——
host 侧在线特征取数是 FATE 自带的桩实现，故 LR 打分恒为 0。链路本身完整
（serving 日志证实 host 侧 `hostInferenceProvider` 参与、`singleInference` 47ms 返回）。
生产接入需实现自定义 adaptor 从本方在线特征源取数——M3 §4.5 一期即声明"用离线特征表模拟在线源"，
属既定范围外的业务集成工作。

**B2｜F7 特征列白名单未实现**：需在 DSL 引入 `feature_selection` 组件，模板 v2 处理。

**B3｜SLA 未定稿**：全环境为 Apple Silicon 上 amd64 仿真（S0 已声明），
训练 173s / AUC 等为功能性数据，性能类 SLA 须在 x86 环境复测。

**B4｜单容器 standalone 拓扑**：guest/host 同容器模拟，跨方 FATE 传输组件（rollsite/osx）
的真实双集群互联未验证——生产拓扑验证需双机环境。

## 4. 与 M3 设计的偏差

| 设计 | 实际 | 说明 |
|---|---|---|
| §4.6 联邦预算不虚构 ε | 遵守 | 联邦任务未扣减隐私预算，仅契约声明 + 审计（设计即如此） |

| ADR-M3-1 对齐用 FATE 内置 | 遵守 | `intersect_count` 已入审计，平台侧 PSI 预检为可选开关（未启用） |

## 5. 结论

**M3 的核心命题「把黑盒训练引擎纳入白盒治理」已验证成立**：FATE 负责密码学与训练，
平台负责契约、审计、模型出库审批——训练、治理、推理三条链路均有活体实测背书，
且部署链路（含 B1 的三层根因修复）已固化为可复现脚本。
生产化前需补：host 侧特征适配器（B1b，业务接入）、B3（x86 性能定稿）、B4（真实双集群拓扑）。
