## 3. 未达成项与遗留（诚实声明）

**B1｜`flow model load` 下发失败（S3 主要缺口）**
- 现象：FATE Flow 接受 load 请求并生成 job，但 job 立即 `retcode 101 failed`；
  serving-proxy / serving-server 侧**无任何请求到达**痕迹；Flow 侧 job 日志目录仅有 audit log，无堆栈；
- 已排除：Serving 组件未起（三组件均已起立并 zk 注册）、servings 地址未配（已指向 proxy:8059 并重启 Flow）、
  推理通道不通（proxy `/federation/v1/inference` 实测返回结构化响应）；
- 待查方向：standalone 模式下 host(10000) 侧 load 子任务的执行路径、
  `flow model load` 对 model_id 的 party 组合校验、1.11.3 与 serving 2.1.6 的 model 协议兼容细节；
- 影响：在线推理无真实分值与延迟基准；**不影响训练与治理链路的验收结论**。

**B2｜F7 特征列白名单未实现**：需在 DSL 引入 `feature_selection` 组件，模板 v2 处理。

**B3｜SLA 未定稿**：全环境为 Apple Silicon 上 amd64 仿真（S0 已声明），
训练 173s / AUC 等为功能性数据，性能类 SLA 须在 x86 环境复测。

**B4｜单容器 standalone 拓扑**：guest/host 同容器模拟，跨方 FATE 传输组件（rollsite/osx）
的真实双集群互联未验证——生产拓扑验证需双机环境。

## 4. 与 M3 设计的偏差

| 设计 | 实际 | 说明 |
|---|---|---|
| §4.6 联邦预算不虚构 ε | 遵守 | 联邦任务未扣减隐私预算，仅契约声明 + 审计（设计即如此） |
| §4.4 出库粒度字段 | 复用 `OutputGranularity` | 未新增契约字段：`INTERSECTION_DETAIL`≈MODEL_EXPORT，其余≈SCORE_ONLY；语义清晰但字段名不贴切，M4 重命名 |
| ADR-M3-1 对齐用 FATE 内置 | 遵守 | `intersect_count` 已入审计，平台侧 PSI 预检为可选开关（未启用） |

## 5. 结论

**M3 的核心命题「把黑盒训练引擎纳入白盒治理」已验证成立**：FATE 负责密码学与训练，
平台负责契约、审计、模型出库审批——训练全链路与治理全链路均有活体实测背书。
在线推理的工程接线剩最后一环（B1），建议作为 M3.5 首个任务在联调环境定位；
生产化前必须补 B3（x86 性能）与 B4（真实双集群）。
