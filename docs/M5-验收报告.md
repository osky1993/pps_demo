# M5 PPS 底座服务化 验收报告

> 版本：v1.0 · 日期：2026-08-02
> 对照：[M5 设计与计划](./M5-PPS底座服务化详细设计与开发实现计划.md)
> 交付基线：`mvn verify` 全绿（gateway 21 项 + 2 项活体集成，全量 96 项）；P1–P3 三次提交

## 1. 目标达成：六缺口逐条对照

M5 把平台从「可运行的隐私计算节点」演进为「业务系统可依赖的底座」。核查确证的六缺口全部闭合：

| 缺口 | 修法 | 证据 |
|---|---|---|
| G1 管理面仅 loopback | `PpsGatewayServer` 绑可配置 host（默认 0.0.0.0） | 构造器 bindHost 参数 |
| G2 无认证鉴权 | HMAC 签名 + 重放窗口 + 常量时间比较；密钥信封加密入库 | 签名错误/时间戳过期/未授权三类拒绝测试 |
| G3 同步阻塞执行 | 异步作业：受理即返回 + 后台工作池 + 并发闸 | 「受理即返回」+ 并发闸实测至多 1 |
| G4 无幂等 | INSERT-first 认领与配额预扣同事务，重放返回原结果 | 同/异步幂等各测：执行只发生一次、不重复扣费 |
| G5 无应用维度 | 应用身份/授权/双层配额 + appId 审计 | 审计含 appId、多应用隔离、配额独立 |
| G6 结果标量出口 | 结果三档（INLINE/PAGED/REF）统一经出库 | 小结果内联、大结果分页拉取 |

## 2. 三期验收

| 期 | 门禁 | 结果 |
|---|---|---|
| **P1 最小可用底座** | 业务系统跨机调用匿踪查询，鉴权/幂等/配额三重生效，审计含 appId | ✅ 接入层 7 + HTTP 3 + 活体（→真实 PIR→user-7 真值 score-607） |
| **P2 异步作业** | PSI/联合统计经 SDK 提交并回调，重发同 reqId 不重复扣预算 | ✅ 异步 6 + 活体（SDK→真实 PSI→签名回调→交集 5000 与真值一致） |
| **P3 生产化** | 能力目录变更双方审批、多应用隔离、可观测 | ✅ 能力治理 2 + 可观测/隔离 3 |

## 3. 核心设计主张的落地

### 3.1 能力目录——把隐私参数从业务手里收回给懂的人

业务系统的调用退化为「能力 id + 业务参数 + 幂等键」，ε/协议/输出粒度**不可见不可覆盖**。
P3 进一步把能力目录做成**持久化 + 双方审批变更**（`CapabilityRegistry`）：单方审批不生效，
双方审批后才 ACTIVE 并对业务可见。**能力目录即数据使用清单，其增删改本身是治理事件。**

### 3.2 服务化不得成为治理后门（实现中的一处修正）

原设计把「双层配额」都放 gateway。实现时判定：数据集级配额若由 gateway 拥有，
**绕过 gateway 即绕过治理**。故修正为——**应用级配额留 gateway（接入 concern），
数据集级配额留 orchestrator（治理 concern，任何入口都强制）**。
这确保直连编排的路径同样受数据集配额约束，服务化外壳无法成为后门。

### 3.3 幂等是正确性要求

隐私计算副作用不可逆（预算扣了、对方已见协商请求），故幂等台账认领与配额预扣**同事务**——
与既有 `ReleaseGateway` 的「先扣后算」同源。同/异步双路径均验证：重发不重复执行、不重复扣费。

### 3.4 审计的隐私边界延续到接入层

接入审计记「哪个 appId、凭哪个 reqId、调哪个能力」，但**PIR 查询键绝不入审计**——
匿踪目标的克制从 M4 延续到服务化层（测试断言审计不含查询键）。

## 4. 不引 MQ 的决策

异步作业用「DB 状态机 + `newCachedThreadPool` + 每能力 Semaphore 并发闸」实现受理/并发/隔离，
零中间件运维负担。单节点日作业量级（百~千）远未到 MQ 门槛；SDK 接口稳定，规模上来可无痛演进。

## 5. 遗留

1. **能力目录管理 UI**：P3 交付的是治理**后端**（CapabilityRegistry），可视化管理台留 M5.5；
2. **多应用隔离压测**：功能隔离已测（配额独立、跨应用不可见），大并发压测需专用环境；
3. **REF 结果档**：以 PAGED 受控访问等价，真正的对象存储签名 URL 待接入对象存储；
4. **SDK 多语言**：当前仅 Java SDK；其他语言可直接按签名规范（手册 §3）自行对接。

## 6. 结论

PPS 已具备作为业务系统隐私计算底座的完整接入能力：**认证、幂等、双层配额、能力目录治理、
同步/异步双模式、结果三档、回调、可观测**，且守住「不绕治理内核」红线。
业务系统接入只需理解「能力 + 幂等键」，无需任何隐私计算知识——这是底座「优雅」的最终体现。
接入方式见 [业务系统接入手册](./M5-业务系统接入手册.md)。
