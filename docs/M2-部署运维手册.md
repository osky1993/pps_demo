# M2 平台一期 部署运维手册

> 版本：v1.0 · 日期：2026-08-01 · 读者：双方机构的节点运维人员（不要求密码学背景）

## 1. 组件与拓扑

每参与方部署一个对等节点，节点内两类进程（均 **JDK 17**，见 §5 FAQ-1）：

| 进程 | 内容 | 通信 |
|---|---|---|
| platform（领域层） | 任务/协商/预算/审计/出库网关/数据接入/PHE | 控制面：HTTPS **mTLS**（默认 18001/18002） |
| psi-engine | mpc4j PSI（进程一任务，platform 按需拉起） | 协议面：netty（默认 19001/19002） |

存储：一期 H2（文件模式 `Database.file(path)`）；生产建议 PostgreSQL（SQL 已保持兼容子集，切换只改 jdbcUrl）。

## 2. 安装步骤（每方各自执行）

```bash

git clone --recurse-submodules <仓库地址> ppc_demo && cd ppc_demo
export JAVA_HOME=<JDK17 路径>
mvn -f third_party/mpc4j/pom.xml install -DskipTests -pl mpc4j-s2pc-pso -am
mvn install -DskipTests
```

```bash
# 2. 证书（一方生成后线下分发，或双方交换 .cer 后各自导入）
./deploy/gen-certs.sh ./deploy/certs 365
```

```bash
# 3. 配置：deploy/node-{a,b}.yaml 改 peer 为对方真实 IP；双方 dataset.seed 必须一致
# 4. 验证安装：单机验收演示（S 档约 10 秒）
mvn -q dependency:build-classpath -Dmdep.outputFile=target/cp.txt -pl engine/ppc-engine-psi
$JAVA_HOME/bin/java --enable-preview --add-modules jdk.incubator.vector \
```

## 3. 运行参数须知

| 项 | 值 | 原因 |
|---|---|---|
| JVM 参数（凡涉 PSI/引擎） | `--enable-preview --add-modules jdk.incubator.vector` | mpc4j preview 约束 |
| 堆内存 | 百万级 `-Xmx8g`；千万级 KKRT16 `-Xmx26g`（机器 32GB） | M1/S0 实测内存档案 |
| GMP 加速（可选） | `-Djna.library.path=<libgmp 目录>`（macOS `/opt/homebrew/lib`，Debian `/usr/lib/x86_64-linux-gnu`） | 消除 javallier 回退告警并提速安全模幂 |
| 协议选型 | ≤300 万 rr22；以上 kkrt16 或 rr22 分批（契约声明 batchLeakageAccepted） | RR22 VOLE 2^22 上限 |

## 3.1 协议面 TLS（M2.5 新增，默认关闭）

PSI 协议流（netty）默认明文（适用专线/VPN 部署）。跨不可信网络时启用 **mTLS 隧道边车**：
netty 明文只绑定 loopback，跨机流量经 `TlsTunnel` 双向认证加密（mpc4j 零改动）。

启用方式：构造引擎 runner 时传入 `ProtocolTlsProfile`（证书直接复用 gen-certs.sh 产物）：

```java
var tls = new ProtocolTlsProfile(
    Path.of("deploy/certs/nodeA.p12"),        // 本方身份库
    Path.of("deploy/certs/nodeA-trust.p12"),  // 只信任对方
    System.getenv("PPC_CERT_PASS"),
    19443,                                     // 本方公网 TLS 端口（对方 tlsPeer 指向它）
    "peer-host:19443");                        // 对方公网 TLS 端点
var engine = SubprocessPsiEngineRunner.currentJvm(600, tls);
```

- 不传 profile = 明文（默认，行为与 M2 一期完全一致）；
- 证书不互信时引擎立即失败（SSLHandshakeException 不重试），有负向门禁测试兜底；
- 防火墙：启用后对外只需放行 TLS 端口，netty 明文端口不再暴露。

## 4. 日常运维

- **预算治理**：新数据集先 `BudgetCenter.ensureAccount` 开户；ε 消耗单调增，重置预算=治理事件，须走机构内审批并留痕；
- **审计**：`AuditCenter.verifyChain()` 应纳入日检；断链=数据库被篡改，立即封存取证；
- **例外出库**（ε=0）：须契约全部参与方在 `exception_approval` 留审批记录，网关才放行；
- **故障处置**：任务 FAILED 后确认外因消除，将任务 FAILED→READY 重跑（幂等：预算只在成功出库时扣一次）；引擎超时会被 launcher 强杀并记 FAILED；
- **证书轮换**：重跑 gen-certs.sh 生成新库 → 双方约定时间窗内同步替换 → 验证控制面连通。

## 5. FAQ

1. **为什么锁 JDK 17？** mpc4j 以 release 17 + preview 编译，17 以外的运行时直接拒载其类文件。platform 领域层本身兼容 17+，待上游去 preview 化后可分离演进。
2. **「can't load Gmp library」告警**：无害回退（纯 Java 模幂），按 §3 配置 jna.library.path 消除。
3. **双机 PSI 起不来**：先后顺序无关（RobustNettyRpc 会重连等待），检查 19001/19002 互通与 yaml 中 peer 地址；两侧 `dataset.seed` 不一致会导致校验失败。
4. **千万级 OOM**：见 §3 内存档案；不满足 32GB 就分批（rr22 分批需契约接受批级泄露）。

## 6. 已知边界（诚实声明）

- ~~协议面 netty 未 TLS~~ **已于 M2.5 解决**（§3.1 隧道边车，默认关闭需显式启用）；隧道为字节级转发，PSI 通信量大时有一次内存拷贝开销（S 档实测无感，千万级建议实测后定案）；
- ~~数据通道 mTLS 端点未落地~~ **已于 M2.5 #2 解决**：控制面服务新增 `/data/{taskId}/{key}` 端点（单载荷上限 8MB），`MtlsDataChannel` 语义为「put 推对方节点、take 取本地存储」——双机联合统计已可跨机（跨节点 mTLS 端到端测试背书）；
- REST 管理 API 与 CLI 未在一期交付（任务操作经领域层 API / 验收演示入口），见验收报告偏差表。
