## 3. 与 M2 计划的偏差（诚实声明）与 backlog

本轮为单机单人（AI 辅助）压缩交付，以下偏差按影响排序，即 M2.5 backlog：

| # | 偏差 | 影响 | 处置 |
|---|---|---|---|
| 1 | 协议面 netty 无 TLS | 跨不可信网络须专线/VPN 兜底 | backlog 首位：netty pipeline 加 SslHandler（RobustNettyRpc 支持注入 Handler，改造点已探明） |
| 2 | 数据通道（公钥/密文Σ）mTLS HTTP 端点未落地 | 双机联合统计暂不可跨机（PSI 任务不受影响） | DataChannel 接口已就位，补 /data 端点即通 |
| 3 | REST API + CLI 未交付 | 机构集成需走领域层 Java API | 计划中的 platform-server（Spring Boot 装配层）整体顺延 |
| 4 | KeyVault 为进程内实现 | 密钥不持久化（任务级密钥语义下可接受） | Vault Transit 对接留接口位 |
| 5 | 真机 LAN/WAN 网络矩阵未测（macOS 无 netem） | SLA 为 localhost 数据 + 通信量推算 | 双机环境就绪后按 S0 报告附录口径补测 |
| 6 | 调度器为编排类直调（无队列/并发控制）、可观测仅审计+日志 | 并发任务量大时需补 | 随 platform-server 一并建设 |
| 7 | ADR 修订：psi-engine 进程一任务（原计划常驻 gRPC 服务） | 无（故障隔离更优，启动开销 S档实测 <1s） | 维持，并发量需要时再服务化 |

## 5. 信通院「可信隐私计算」对标速览（gap 分析摘要）

| 评测维度 | 现状 | gap |
|---|---|---|
| 算法与协议（PSI/半同态/DP） | 具备，含选型与分批 | 恶意模型（RR22 MALICIOUS 档 mpc4j 已支持，平台未暴露） |

| 治理与审计 | 预算/例外审批/哈希链审计 | 审计签名（当前哈希链）、三员分立角色体系 |

## 6. 结论

M2 平台一期核心目标——**把 M1 验证的三条技术路线装进一个有治理能力的对等节点平台**——已实现并有 49 项自动化测试与可复现验收演示背书。遗留缺口集中在传输加固与管理面工程化（§3 表），无架构性风险。建议按 backlog 顺序进入 M2.5 收尾，并行启动 M3（联邦学习集成）预研。
