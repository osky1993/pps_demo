## 2. H1：PSI 性能矩阵（假设：千万级专线分钟级）

### 2.1 结果矩阵（loopback）

| 协议 | S 档 | M 档 | L 档 |
|---|---|---|---|
| **RR22** | 440 ms / 2.4 MB | **9.5 s / 50.0 MB** | 单批不可行（见 2.2 ①） |
| **KKRT16** | 170 ms / 1.5 MB | 16.5 s / 149.9 MB | **169.8 s / 1356 MB**（`-Xmx26g`） |

（格式：耗时 / 双向通信量。M 档交集 30 万条，L 档交集 100 万条，均校验通过。）

### 2.2 两条硬约束（M2 必须继承）

① **RR22 单批输入上限约 300 万条**：底层 WYKW21 VOLE 实现校验
   `num ≤ 2^22 = 4,194,304`，输入经 OKVS 膨胀（实测 1000 万 → 13,481,104，约 1.35×）后超限即抛
   `IllegalArgumentException`。千万级用 RR22 需分批求交，且每批交集规模泄露需写入安全声明；

② **KKRT16 千万级内存档案**：`-Xmx12g` 服务端线程 OOM，`-Xmx26g` 通过。
   M2 容器规格按"千万级 PSI 节点 32 GB"起步。

### 2.3 判定

**H1 成立。** 笔记本 + 纯 Java + loopback 即达 2.8 分钟；真实专线下通信量将成主导
（1.36 GB @ 100 Mbps ≈ 追加约 2 分钟），仍在"分钟级"承诺内，且 native 加速、服务器硬件的余量均未动用。
协议选型结论：**百万级以内 RR22 全面占优（时间 ×1.7、通信量 ×3 的优势），千万级 KKRT16 或 RR22 分批**。

## 3. H2：Paillier 密文聚合（假设：百万级单节点分钟级）

### 3.1 分阶段吞吐（2048 位密钥，8 并行）

| 阶段 | 纯 Java（n=10万） | GMP 加速（n=1万） | 吞吐结论 |
|---|---|---|---|
| keygen | 92 ms | 430 ms* | 一次性成本，可忽略 |
| encrypt（未盲化 g^m 快速路径） | 41 ms | 8 ms | **~240 万条/秒**，非瓶颈 |
| **obfuscate（盲化 r^n mod n²）** | **159.7 s** | **10.6 s** | **626 → 945 条/秒，唯一瓶颈** |
| 密文累加 | 2.4 s | 0.24 s | ~4.2 万条/秒 |
| decrypt（单结果） | 2 ms | 2 ms | 可忽略 |

\* keygen 为随机素数生成，波动大，单次数据仅供参考。
单密文 512 B → 百万条全量传输约 488 MB。

### 3.2 外推与瓶颈解读

逐条盲化 100 万条：945 条/秒 ÷ 8 并行外推 ≈ **18 分钟**（纯 Java 27 分钟），字面超出"分钟级"。
GMP 仅提速 1.5×，因 javallier 走 GMP 常数时间安全模幂（抗时序攻击，本身慢于非安全版）。

### 3.3 三条缓解路径（按推荐序）

1. **盲化时机跟随数据出域边界**（已在 H4 端到端实测验证）：密态聚合类链路只有最终 Σ 出域，
   只盲化一次 → 30 万条聚合实测 **1.5 秒**，瓶颈整体消失。应成为 M2 PHE 引擎的默认设计；
2. **盲化因子离线预计算**：r^n 与消息无关，空闲期预生成，在线只剩一次模乘（~4 万条/秒级）；
3. 服务器核数线性扩展（盲化无共享状态，实测并行无锁竞争）。

### 3.4 判定

**H2 临界达标：** 功能与正确性无问题；"逐条盲化 + 百万级 + 分钟级"三者同时成立需依赖缓解路径 2，
但真实业务链路（聚合出域）中瓶颈天然消失。**不构成 Go/No-Go 障碍。**

## 4. H3：DP 误差矩阵（假设：加噪出库误差可控）

### 4.1 相对误差分位数（重复采样 1000 次；mean 为 BoundedMean 实测 10万×100 次）

| ε | count(n=100万) P50 / P95 / P99 | sum(n=100万) P50 / P95 / P99 | mean(n=10万) P50 / P95 / P99 |
|---|---|---|---|
| 0.1 | 0.0007% / 0.0030% / 0.0046% | 0.0118% / 0.0492% / 0.0755% | 0.1546% / 0.6468% / 0.7746% |
| 1.0 | 0.0001% / 0.0003% / 0.0005% | 0.0012% / 0.0052% / 0.0078% | 0.0176% / 0.0624% / 0.0837% |
| 10 | ≈0% | 0.0001% / 0.0005% / 0.0008% | 0.0014% / 0.0079% / 0.0101% |

（clamp=[0, 100000] 分；sum 的 L1 敏感度 = clampUpper。）

### 4.2 给业务方的直观口径

百万级数据、ε=1.0 时：一次 sum 查询的误差 99% 情况下不超过万分之一——**对报表类业务完全无感**。
即使取合规上偏保守的 ε=0.1，P99 误差也在千分之一以内。真正需要业务决策的是
**clamp 边界**（给大→噪声大，给小→截断偏差）与**预算总额**（决定同一数据集可出库多少次）。

### 4.3 治理语义验证

- 预算熔断：budgetTotal=10、单次 ε=1.0，第 11 次查询抛 `BudgetExhaustedException` 且失败不扣减；
- 数据集间预算独立记账；
- 剖析方法论：count/sum 为"确定性聚合 + 拉普拉斯噪声"，聚合一次、噪声重复采样（与原语数学同源）；
  mean 误差结构为商式，用真实 BoundedMean 小样本实测。

### 4.4 判定

**H3 成立。** Google DP Java 库工程质量高，四条路线中集成成本最低，零妥协。

## 5. H4：端到端链路（假设：三组件可串成业务闭环）

场景：A 银行 × B 电商联合统计「共同客户在 B 平台的年消费总额」（任务 d0e60fda，M 档，ε=1.0）。

| # | 阶段 | 耗时 | 披露控制 |
|---|---|---|---|
| 1 | PSI 求交（RR22，100万×100万 → 交集 30 万） | 22.1 s* | 双方仅见交集（PoC 设定，平台终态支持仅出基数） |
| 2 | Paillier 公钥分发 | <1 ms | 公钥经字节边界传输 |
| 3 | B 方密态聚合 30 万条（仅盲化最终Σ） | **1.5 s** | 单条明细密文不出域 |
| 4 | A 方解密真实总额 | <100 ms | 真值仅 A 内部可见，禁止直接出库 |
| 5 | DP 网关出库（扣减 ε=1.0） | <100 ms | 实测偏差 **0.0008%**，预算留痕 |

\* 高于独立基准 9.5 s，因测量时后台有 L 档任务抢占 CPU，属测量环境噪声。

密态聚合结果与明文对照全量一致；审计 JSON（任务/协议/交集规模/ε 消耗/预算余额/分阶段耗时）随任务落盘。
跨方数据全部经 `Transport` 字节接口传递（序列化已证明），双机化仅需替换该接口实现。

**H4 判定：成立。**

## 7. 与假设的偏差分析及遗留项

| 偏差 | 影响 | 处置 |
|---|---|---|
| 网络矩阵（LAN / WAN-sim）未执行 | H1 的"专线"限定词未直接验证，仅以通信量推算 | **遗留项 1**：双机 netty RPC + tc/netem，M2 立项前补 |
| 测量纪律为单次运行 | 数据波动未量化 | 遗留项 2：正式 SLA 基准按 §7.2 纪律重测 |
| RR22 千万级分批未实现 | L 档 RR22 无数据 | 遗留项 3：分批求交 PoC |
| 盲化因子预计算未实现 | H2 缓解路径 2 为推算值 | 遗留项 4：预计算 PoC（低风险，模乘吞吐已实测） |
| PSI native-tool 加速未启用 | 现有数据为保守下限 | 可选项：M2 性能优化期评估 |

## 8. Go / No-Go 建议

**GO。**

- 四条假设：三条成立，一条（H2）临界且瓶颈在真实业务链路中天然消失、缓解路径明确；
- 全部实测数据未动用 native 加速与服务器硬件，为保守下限；
- 未发现任何阻断 M2 立项的技术风险；三库风险均有已验证的对策或备份路径；
- 遗留项 1（网络矩阵）建议作为 M2 立项条件而非 M1 阻塞项——loopback 数据 + 通信量推算已足够支撑量级判断。
