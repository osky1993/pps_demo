## 1. M2 的定位与目标

### 1.1 定位

M1 证明了「技术可行」；M2 要交付「**可给真实的两个机构部署使用的平台**」。
一句话目标：**支持隐私求交（PSI）与联合统计（PSI→密态聚合→DP 出库）两类任务的
对等节点平台，具备生产级的任务管理、安全通信、隐私预算治理与审计能力。**

### 1.2 验收标准（Exit Criteria）

1. **双机双节点**部署（真实两台机器、真实网络），A 方发起、B 方审批的完整任务流跑通：
   - 任务一：PSI 求交（输出交集明细或仅基数，由任务定义决定）；
   - 任务二：联合统计（M1 的 E2E 链路平台化：PSI → B 方密态聚合 → A 方解密 → DP 出库）；
2. 所有跨方通信走 **mTLS**，Paillier 密钥经 **KMS** 管理，出库结果强制过 **DP 网关**；
3. 隐私预算**持久化记账**（重启不丢），超限熔断，例外需审批留痕；
4. 任务级**审计日志**可查询（谁、何时、什么数据、什么协议、输出什么、消耗多少预算）；
5. 性能达到 §4.9 的 SLA（以 Sprint 0 双机实测修正后的口径为准）；
6. 交付物：可部署制品（容器镜像 + compose/K8s 清单）、部署手册、API 文档、验收演示脚本。

### 1.3 明确不做（Out of Scope，防 scope creep 的红线）

- 联邦学习 / FATE 集成（M3）；FHE sidecar（M4）；
- 三方及以上的多方任务（架构预留 partyId 列表，实现只做两方）；
- Web 控制台 UI（一期只交付 REST API + CLI，UI 是 M2.5/M3 的事）；
- 跨任务的数据集市/元数据管理平台（只做任务内的数据接入）；
- 信通院送测（一期做对标 gap 分析，送测另立项）。

### 1.4 M1 硬约束与设计输入（必须继承）

| # | M1 结论 | 对 M2 设计的强制约束 |
|---|---|---|
| C1 | mpc4j 绑定 JDK 17 + `--enable-preview` | **PSI 引擎必须独立进程**（独立 JVM 17），不得与平台主进程（可用 LTS 演进）同 JVM |
| C2 | RR22 单批上限约 300 万条 | 协议自动选型 + RR22 分批求交组件（Sprint 0 验证） |
| C3 | KKRT16 千万级需 26GB 堆 | 节点容器规格分档：标准 8GB / 大任务 32GB，调度器按任务规模选择 |
| C4 | 逐条盲化 945 条/秒，仅盲化出域 Σ 则瓶颈消失 | PHE 引擎的盲化策略是**显式设计维度**：按「数据出域边界」决定盲化对象；补充盲化因子预计算池 |
| C5 | `EnvType.STANDARD_JDK` 纯 Java 路径 | 默认纯 Java；native-tool 作为性能优化开关（非功能依赖） |
| C6 | DP 出库唯一通道 + 预算先扣减语义已验证 | `BudgetLedger`/`DpAggregator` 接口形态直接升级为预算中心，语义不变、存储换持久化 |

## 2. 需求分析

### 2.1 角色与用例

| 角色 | 说明 | 核心用例 |
|---|---|---|
| 发起方业务员（A 方） | 出题方 | 创建任务（选数据集、协议、输出粒度、ε）、查看结果 |
| 数据方审批员（B 方） | 数据供给方 | 审批/拒绝任务、绑定本方数据集、查看本方参与记录 |
| 节点运维 | 双方各自的 IT | 部署节点、配置证书/KMS/数据源、监控 |
| 合规审计员 | 双方或第三方 | 查询审计日志、预算消耗报表、例外审批 |

**关键流程（两方任务协商）**：A 创建任务 → 平台生成任务契约（数据集指纹、协议、
输出粒度、ε、clamp 边界）→ 推送 B 方节点 → B 审批（可拒绝）→ 双方节点按契约执行 →
结果经 A 方 DP 网关出库 → 双方各自留审计。**契约一经双方确认不可变更**（重新协商 = 新任务）。

### 2.2 功能需求清单

| 编号 | 需求 | 优先级 |
|---|---|---|
| F1 | 任务生命周期管理（创建/协商/审批/执行/取消/查询），状态机驱动 | P0 |
| F2 | PSI 任务：RR22/KKRT16/自动选型；输出粒度可选（明细 / 仅基数） | P0 |
| F3 | 联合统计任务：PSI→密态聚合→DP 出库 DAG | P0 |
| F4 | 隐私预算中心：按数据集持久化记账、熔断、例外审批 | P0 |
| F5 | 审计中心：append-only 任务事件流 + 查询 API | P0 |
| F6 | 数据接入：JDBC（PostgreSQL/MySQL）与 CSV 文件两种 connector，字段映射到 (id, value) | P0 |
| F7 | 安全基座：mTLS 双向认证、Paillier 密钥入 KMS（Vault）、证书轮换手册 | P0 |
| F8 | 断点与重试：网络闪断自动重连；引擎崩溃任务标记失败可重跑（幂等） | P1 |
| F9 | RR22 分批求交（千万级），含分批泄露的契约声明 | P1 |
| F10 | 盲化因子预计算池（后台填充，encryptAndObfuscate 走池） | P1 |
| F11 | 可观测：结构化日志、任务指标（耗时/通信量/预算）Prometheus 暴露 | P1 |
| F12 | CLI 客户端（创建任务、审批、查结果、查审计） | P1 |

### 2.3 非功能需求

- **安全**：跨方零明文（协议密态 + mTLS）；节点内密钥不落盘明文；最小披露在契约层强制；
- **性能 SLA**：见 §4.9（Sprint 0 修正）；
- **可部署性**：单容器镜像 × N 进程 或 compose 三容器；离线安装包（内网交付常态）；
- **可审计**：审计流 append-only，防篡改（哈希链一期即可，签名留二期）。

## 3. 总体架构（节点内细化）

### 3.1 进程拓扑（单节点）

```
┌────────────────────────── 隐私计算节点（每参与方一套，对等） ──────────────────────────┐
│                                                                                      │
│  ┌─────────── platform 进程（Spring Boot 3.x / JDK 21 LTS）───────────┐              │
│  │  REST API（任务/审批/查询/审计）        ← 业务系统 & CLI 接入        │              │
│  │  任务调度器（DAG 状态机）                                           │              │
│  │  跨方控制面 gRPC 客户端/服务端（mTLS）  ← 任务协商、密文/公钥传递     │              │
│  │  预算中心 · 审计中心 · 数据接入 connector                            │              │
│  │  PHE 引擎（javallier + 预计算池）· DP 网关（Google DP）              │              │
│  └───────────────┬────────────────────────────────────────────────────┘              │
│                  │ 本机 gRPC（localhost，任务粒度调用）                                │
│  ┌───────────────▼──────────────────────────────┐                                    │
│  │  psi-engine 进程（JDK 17 + preview，独立 JVM） │  ← C1 约束的落点                  │
│  │  mpc4j netty RPC 端点（对方 psi-engine 直连）   │                                    │
│  │  协议选型 · 分批求交 · EnvType 纯 Java          │                                    │
│  └──────────────────────────────────────────────┘                                    │
│                                                                                      │
│  PostgreSQL（任务/预算/审计/契约）      Vault（Paillier 私钥、mTLS 证书材料）           │
└──────────────────────────────────────────────────────────────────────────────────────┘
         │  控制面：platform ⇄ platform（gRPC + mTLS，端口 1）
         │  协议面：psi-engine ⇄ psi-engine（mpc4j netty + TLS，端口 2）
         ▼
                    对方节点（同构对等）
```

**架构决策记录（ADR 摘要）**：

- **ADR-1 PSI 独立进程**：C1 强制。platform 用 JDK 21 LTS 正常演进，psi-engine 锁 JDK 17；
  两者经本机 gRPC 通信，psi-engine 崩溃不拖垮平台（故障隔离红利）；
- **ADR-2 PHE/DP 内嵌 platform 进程**：两者是纯库（javallier/Google DP 无 JDK 特殊约束），
  独立进程徒增运维复杂度；预计算池是 platform 内后台线程；
- **ADR-3 控制面与协议面分离**：任务协商/密文传递走自研 gRPC（可控、可审计）；
  PSI 协议流走 mpc4j 自带 netty（不重写协议传输，M1 的 `LocalPsiRunner` 薄封装模式延续）；
- **ADR-4 存储选 PostgreSQL**：任务/预算/审计都是强事务小数据量，单库多 schema 足够；
  预算扣减用行级锁 + 事务保证「先扣减后加噪」原子性；
- **ADR-5 KMS 选 Vault**：开源、内网可部署、Transit 引擎托管 Paillier 私钥；
  抽象 `KeyVault` 接口，云 KMS 留实现位。

### 3.2 模块与工程结构（现仓库演进）

```
ppc_demo/
├── ppc-common / ppc-psi / ppc-phe / ppc-dp / ppc-e2e / ppc-bench   # M1 资产，保留
├── platform/
│   ├── ppc-platform-api        # DTO、任务契约、状态机定义（无框架依赖）
│   ├── ppc-platform-core       # 调度器、协商流程、预算中心、审计中心（Spring 无关的领域层）
│   ├── ppc-platform-server     # Spring Boot 装配：REST、gRPC、JPA、安全
│   ├── ppc-platform-connector  # JDBC / CSV 数据接入
│   └── ppc-platform-cli        # picocli 命令行客户端
├── engine/
│   └── ppc-engine-psi          # 独立 JVM17 进程：gRPC 服务壳 + 复用 ppc-psi 协议层
└── deploy/                     # Dockerfile ×2、compose 双节点样例、K8s 清单、证书生成脚本
```

依赖方向：`server → core → api`；`core` 不依赖 Spring（可单测可移植）。
M1 的 `LocalPsiRunner`、`PaillierAggregator`、`DpAggregator`、`BudgetLedger`、`AuditRecord`
分别升级进 `ppc-engine-psi` / `core`，接口语义不变（M1 §10 移交物兑现）。

## 4. 关键设计

### 4.1 任务模型与状态机

```
CREATED ──提交──▶ NEGOTIATING ──B审批通过──▶ READY ──调度──▶ RUNNING ──▶ RELEASING ──▶ SUCCEEDED
   │                  │                                        │              │
   └──取消──▶ CANCELLED◀──B拒绝──┘                    失败(可重跑)▼      DP网关拒绝▼
                                                            FAILED         REJECTED
```

- **任务契约（TaskContract）**：taskId、taskType（PSI / JOINT_STATS）、双方 partyId、
  数据集引用与**内容指纹**（行数 + 抽样哈希，防审批后换数据）、协议与参数、
  **输出粒度**（INTERSECTION_DETAIL / CARDINALITY_ONLY / NOISED_SCALAR）、ε、clamp、审批人。
  契约双方各存一份，执行前互验指纹一致；
- **RELEASING 独立成态**：出库是治理关口（预算扣减 + 加噪 + 审计），失败语义与计算失败不同；
- 状态迁移全部落审计事件（见 4.5）。

### 4.2 PSI 引擎生产化

- **双机化**：`LocalPsiRunner` 的 `MemoryRpcManager` 替换为 mpc4j `NettyRpcManager`
  （Sprint 0 首个任务，M1 遗留项 1）；连接参数来自任务契约；netty 层开 TLS；
- **协议自动选型**（可被契约显式覆盖）：

| 双方最大集合规模 | 默认协议 | 依据（M1 实测） |
|---|---|---|
| ≤ 300 万 | RR22 | 时间 ×1.7、通信 ×3 优势 |
| > 300 万 | KKRT16（默认）或 RR22 分批（契约显式选择） | C2 上限；C3 内存档案决定调度到 32GB 规格 |

- **RR22 分批求交（F9）**：client 侧集合按 ≤256 万/批切分，逐批与 server 全集求交后并集；
  **每批交集规模会泄露**——契约中 `batchLeakageAccepted=true` 才允许选择，审计记录批数；
- **断点重试（F8）**：PSI 协议本身不支持断点续传（协议状态在内存），重试 = 整任务重跑；
  调度器保证幂等（同一契约重跑不重复扣预算——预算在 RELEASING 阶段才扣）；
- **输出粒度**：CARDINALITY_ONLY 时 psi-engine 只回传基数给 platform，交集明细在引擎内丢弃。

### 4.3 PHE 引擎生产化

- **盲化策略显式化（C4 落点）**：引擎 API 区分
  `encryptForAggregation`（不盲化，仅限本地聚合链路）与 `encryptForTransfer`（必须盲化）；
  聚合结果出域前强制 `obfuscate`——**「密文是否出域」由 DAG 边决定，编译期即可校验**；
- **盲化因子预计算池（F10）**：后台线程按池水位（默认 10 万）预生成 r^n mod n²，
  `encryptForTransfer` 从池中取因子做一次模乘；池耗尽降级为同步计算（限流告警）。
  预期在线吞吐从 945 条/秒 → 4 万条/秒级（Sprint 0 验证）；
- **密钥生命周期（F7）**：任务级密钥对（一任务一对，任务结束标记销毁）；
  私钥生成后立即入 Vault Transit，platform 内存仅持句柄；公钥随契约分发。

### 4.4 DP 网关与预算中心

- M1 `BudgetLedger` 语义（先扣减后加噪、失败不扣、数据集隔离）平移到 PostgreSQL：
  `budget_account(dataset_id, total, spent)` + 行级锁事务扣减；
- **出库唯一通道**：platform 对外的任何结果读取 API 只能返回 `release_record` 表内容，
  该表唯一写入方是 DP 网关（代码层 + DB 权限双重保证）；
- **例外审批**：`epsilon=0`（不加噪出库）必须契约声明 + 双方审批人签字段 + 审计高亮；
- 预算报表 API：按数据集的消耗曲线（合规审计员用例）。

### 4.5 审计中心

- 事件模型：`audit_event(seq, task_id, party, event_type, payload_json, prev_hash, hash)`
  ——append-only + 哈希链（每条含前条哈希，篡改即断链）；
- 事件类型：任务态迁移、契约确认、指纹校验、协议启动/完成（含通信量）、
  预算扣减、出库、例外审批、引擎异常；
- M1 `AuditRecord` 的字段集是 payload 的起点；查询 API 按任务/时间/类型过滤。

### 4.6 数据接入（F6）

- `DatasetRef = connector 类型 + 连接参数 + 字段映射（idColumn, valueColumn?）`；
- JDBC connector：流式读取（千万级不整表入内存），值列按「×100 取整」编码规范转换（M1 规范平台化）；
- 契约中的数据集指纹 = 行数 + 有序抽样 1000 行的 SHA-256，审批后执行前复核。

### 4.7 安全基座（F7）

- **mTLS**：联盟 CA（一期可用脚本化自签根）签发节点证书；控制面 gRPC 与协议面 netty 均双向校验；
  证书指纹登记进对方节点配置（防中间人）；`deploy/` 提供证书生成与轮换脚本；
- **Vault**：dev 模式起步、部署手册给生产配置要点；`KeyVault` 接口隔离；
- **最小披露强制**：输出粒度、ε、clamp 全部在契约层声明并双方确认，执行层只按契约放行。

### 4.8 可观测（F11）

结构化 JSON 日志（含 taskId 贯穿）；Micrometer + Prometheus 端点：
任务耗时分阶段直方图、PSI 通信字节、预算余额 gauge、预计算池水位。

### 4.9 性能 SLA（初稿，Sprint 0 双机实测后定稿）

| 场景 | 目标（LAN/专线） | 依据 |
|---|---|---|
| PSI 100万×100万 | ≤ 60 s | M1 loopback 9.5s + 50MB 通信 @100Mbps ≈ +4s，余量给协商与调度 |
| PSI 1000万×1000万 | ≤ 10 min | M1 loopback 2.8min + 1.36GB @100Mbps ≈ +2min |
| 联合统计（100万 对齐 30万聚合） | ≤ 90 s | M1 E2E 全链路 <25s + 网络修正 |
| 预计算池在线加密出域 | ≥ 1 万条/秒 | C4 缓解路径 2，Sprint 0 实测修正 |
| 出库 API P99 | ≤ 500 ms | 网关 + DB 事务 |

## 5. 开发实现计划（6 × 双周 Sprint）

### 5.1 人力假设

3 人：**E1 协议线**（PSI 引擎、PHE 引擎、Sprint 0 验证）、**E2 平台线**（调度、协商、预算、审计）、
**E3 工程线**（安全基座、connector、部署、CI、测试设施）。2 人则砍 F9/F10/F12 至 P2，周期 +40%。

### 5.2 Sprint 计划

| Sprint | 主题 | 关键交付 | 验收检查点 |
|---|---|---|---|
| **S0（M1 遗留项清偿 + 立项定稿）** | 双机实测 | E1：netty 双机 PSI（遗留项1）+ LAN/netem 网络矩阵（遗留项2 纪律：5次取中位）+ RR22 分批 PoC（遗留项3）+ 盲化预计算 PoC（遗留项4）；E2：任务模型/契约/状态机详设评审；E3：双机环境、证书脚本、CI 骨架 | **CP0：SLA（§4.9）以实测定稿；分批泄露与预计算吞吐有数据**；未达标项按 §6 熔断规则处理 |

## 7. 测试策略

- **单元/领域**：core 层（状态机、预算、审计链、选型器）纯 JVM 测试，目标行覆盖 >80%；
- **契约测试**：platform⇄psi-engine gRPC、节点⇄节点控制面，用固定用例集双向验证；
- **集成**：Testcontainers（PostgreSQL + Vault dev）跑单节点全流程；
  双节点用 compose 在 CI 起「双容器对跑」冒烟（S 档）；
- **性能回归**：M1 的 `ppc-bench` 基线扩展为平台任务级基准，每 Sprint 末对 SLA 出趋势；
- **故障演练**（S4/S5）：拔网线、杀 psi-engine、Vault 不可用、预算并发扣减竞争。
